# Windows 原生重构设计

## 目标

新版不是给旧界面换皮，而是重排整条现场数据链路：

1. WPF 窗口先出现并立即允许输入；
2. 内置确定性别名立即可用；
3. 全国地点库、旧版自定义别名、工信部电台型号库在后台只读装载；
4. 每次 `Enter` 只执行一次短 SQLite 原子事务；
5. Excel 导出、资料同步、画像重算全部离开录入热路径；
6. 未识别型号和 token 原样保存，不能因资料库缺项而丢失；
7. 正式迁移前，原生预览使用独立数据库，不改旧库。

## 技术选择

- **C# + .NET 10 + WPF**：使用 .NET 10 SDK 和桌面运行时，无需安装 WinUI 工作负载；标准窗口边框天然支持拖动缩放、DPI 和辅助功能。当前验收构建使用独立 SDK 目录，不改动系统已有 .NET 8。
- **Microsoft.Data.Sqlite**：继续使用 SQLite，采用 WAL、外键、唯一序号和事务；工信部/QTH/旧库均以只读方式打开。
- **零 UI 框架依赖**：不引入 Material、Fluent UI 或大型 MVVM 框架，控件、命令和动画均由 WPF 原生能力实现。
- **后台资料快照**：解析器始终读取不可变快照，资料重载完成后一次替换，不在键盘事件里访问网络或扫描数据库。

## 运行链路

```text
键盘输入
   │
   ├─ 内存确定性解析 ──→ 结构化预览 / 互斥候选 / 未识别原文
   │
 Enter
   │
   └─ SQLite 原子事务 ──→ 立即显示新行
                              │
                              ├─ 后台画像更新
                              ├─ 后台 Excel 批次（后续阶段）
                              └─ 后台资料库更新（后续阶段）
```

解析优先级固定为：

```text
用户/本地确认别名 > 稳定历史 > 工信部精确型号 > 未收录型号原文
```

因此工信部里存在其他厂商的 `R6` 时，本地确认的 `r6 → 摩托罗拉 R6` 仍然优先。型号搜索和现场解析都不隐式联网。

## QTH

- 后台读取现有全国行政区库，目前实测 2,521 条行政区、约 9,600 个规范键与别名。
- `njxw` 输出 `江苏省南京市玄武区`，不再只写 `南京玄武`。
- 老版自定义 QTH 别名会与全国地点记录合并，优先保留完整省市区。
- 道路、学校、地标需要后续独立 POI 缓存；没有可靠证据时只保留原文，不伪造上级行政区。

实际 XAML 效果图：[`native-ui-actual.png`](native-ui-actual.png)

概念设计参考：[`native-ui-concept.png`](native-ui-concept.png)

动画严格限制在视觉反馈：

- 页面切换：淡入 + 4 px 横移，90–95 ms；
- 解析卡片：不做逐字回写动画，只在视觉层更新当前快照；
- 提交成功：全窗淡绿色闪烁，110 ms；
- Windows 关闭“在 Windows 中显示动画”或软件关闭动画后，全部直接切换；
- 动画不包裹解析、SQLite 提交或后台队列，不会延迟 `Enter`。

## 数据边界

当前原生验收版写入：

```text
%LOCALAPPDATA%\HAM点名助手\data\ham_checkin_native.db
```

只读使用：

```text
%LOCALAPPDATA%\HAM点名助手\data\ham_checkin.db
%LOCALAPPDATA%\HAM点名助手\data\qth_places.db
%LOCALAPPDATA%\HAM点名助手\data\miit_radio_catalog.db
```

当前不会：

- 修改、迁移或删除旧版真实数据库；
- 自动连接当前打开的 Excel；
- 控制鼠标、键盘或其他桌面软件；
- 将测试数据写入真实点名库；
- 改变旧版 GitHub 自动更新通道。

## 性能预算

| 项目 | 目标 |
|---|---:|
| 已显示窗口到可输入 | 冷启动小于 1 秒，热启动小于 500 ms |
| 内存解析 p95 | 小于 1 ms |
| SQLite 单条提交平均值 | 小于 2 ms |
| 任一 UI 线程连续工作 | 小于 8 ms |
| 页面过渡 | 90–95 ms，可关闭 |
| Excel 对录入延迟 | 0 ms（不在热路径） |

性能数字必须由 `HamCheckin.Native.Benchmarks` 实测产生，不以设计目标冒充结果。

## 完整替换前仍需完成

当前交付是可运行的原生核心预览，不是旧版功能等价替换。正式替换还需要：

1. 旧数据库双向兼容和带回滚的迁移工具；
2. 场次新建、选择、结束以及本地/外部场次边界；
3. 可重试的 Excel 后台队列、导出和一致性检查；
4. QTH 道路/地标 POI 增量缓存与证据展示；
5. 工信部电台库真实官网全量同步验收与错误恢复；
6. 补全批次、审计和安全撤销；
7. GitHub 更新通道、签名和正式安装包；
8. 真实名单金标准回归以及长时间连续输入测试。

只有这些完成并通过迁移演练后，才应让原生版写入现有生产库或替换旧版更新渠道。
